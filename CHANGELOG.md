# Changelog

## Unreleased

### Backward-incompatible changes

- **Every session in flight at the moment of the bump has its pending work interrupted.** eve's 0.57.0 rewrite of the turn-execution model imports each session created under the pre-0.57.0 driver/turn model into the new model on its next delivery — identity, history and the event stream are kept — but work that was in flight during the bump, including an approval card waiting on a click, is interrupted rather than resumed. Drain approvals and bump at a quiet hour, never mid-turn; no migration restores interrupted mid-flight work. (LAR-69)
- **`@workflow/world-postgres` moves with eve, `5.0.0-beta.32` → `5.0.0-beta.42`.** eve vendors its own `@workflow/world-local` copy and states no compatible range for the app-supplied `world-postgres`; `beta.42` is the only published `world-postgres` whose own `world-local` pin (`beta.44`) matches the copy eve 0.60.1 vendors. Update the pin in every service that declares `@workflow/world-postgres`. (LAR-69)
- **`zod` moves `4.4.3` → `4.5.4`.** `@workflow/world-postgres@5.0.0-beta.42` requires `zod ~4.5.4`; every workspace package that pins zod exactly (`packages/agent-kit`, `packages/board-evals`, `services/chief-of-staff`, `services/creative`, `services/keeper`, `services/travel`) needs the same version so the workspace resolves one zod. (LAR-69)
- **`ai` floor moves `^7.0.58` → `^7.0.105`.** eve 0.60.1's own peer requirement is `^7.0.105`; the packages and services that declare `"ai": "^7.0.58"` should raise their floor to match, even though the existing caret range already resolves a satisfying version today. (LAR-69)
- **Node engine floor corrected `>=22` → `>=24` in the root `package.json`.** eve has required Node 24 since before the currently pinned 0.32.0 (`engines.node` is `>=24` in both the 0.32.0 and 0.60.1 packages); the manifest understated it. (LAR-69)
- **eve CLI telemetry is disabled everywhere `eve build` or `eve extension build` can run** — every Dockerfile builder stage, every builder workflow, the keeper runtime-images workflow, and the board-evals scripts — via `EVE_TELEMETRY_DISABLED=1`. The running agent never sent anything; only the CLI's build/install path does. (LAR-69)
- **No database migration is required by this release.** The bump changes dependency pins, the vendored patch and instrumentation policy only; nothing under any service's `sql/` changes. (LAR-69)

## v0.3.0-rc.1 — 2026-09-16

- **feature** — The permissions board: the console's Integrations page shows, for every agent and integration, whether it acts on its own, asks first or never acts, who set that and when, and what happened in the last 30 days. A change reaches the agent at its next action.
- **feature** — The console lists the agents that actually run (each agent registers itself when it starts).
- **security** — Some actions always ask first, whatever is set: moving money, deleting data, contacting someone for the first time, publishing, and an agent changing its own autonomy. Setting an integration to 🚫 refuses them outright.
- **fix** — The permission switches on the console now reach the agents for every action that asks first; integrations whose actions never ask (plain writes) are shown as such instead of with a switch that did nothing.
- **note** — Until the next step, keep email and calendar on "asks first": Saga's own instructions still say every send shows a card.
- **feature** — "Forget this" now asks before it deletes a stored fact.
- **feature** — Deleting a note from the Brain vault always asks first.
- **feature** — First contact is decided per recipient: when email or calendar is set to act on its own, a message or invitation goes out without a card only if you have written to every recipient before (in mail or in your network); anyone new still asks. The CRM does not count, and mail someone sent you does not count.
- **security** — An email's subject and reply headers can no longer carry extra recipients or headers.
