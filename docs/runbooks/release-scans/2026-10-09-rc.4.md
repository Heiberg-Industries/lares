## Gateway v1.101.6 checks

Run on a throwaway local stack: a private Postgres from the rc.3 db pin, and the gateway started
through the engine's own `images/gateway-runtime/start.sh` with `config.yaml` rendered by
`services/box/lib/gateway-config.ts` and file-mounted placeholder secrets. No provider was called.

| # | Check | Result |
| --- | --- | --- |
| G1 | cosign signature against LiteLLM's published key | **passed** |
| G2 | Start, upgrade in place, roll back | **passed.** v1.101.0 created the gateway database (165 migrations). v1.101.6 on the same database: live, ready, "No pending migrations", litellm 1.101.6 and proxy-extras 0.4.94. Restarting on v1.101.0 afterwards also started cleanly with no pending migrations. |
| G3 | Keeper key lifecycle | **passed.** The keeper's own `LiteLLMGatewayKeys` code created a key on v1.101.0. After the upgrade it found that key with the exact policy, created a second key, read it back, deleted it, and confirmed it was gone. The first key was still present after rolling back. |
| G4 | `/key/info` with an agent key | **unchanged from v1.101.0.** `litellm-key-info.live.mts` gets 403 on both self-read forms, the same as its recorded v1.101.0 run. Agent keys still cannot read their own spend. `/key/generate` with an agent key is refused (403), as required. |
| G5 | Alias routing | **passed**, with the alias pointed at a local mock provider for this check only. A key scoped to the alias reached the mock (200). A key scoped to another alias was refused with `key_model_access_denied` (403). |
| G6 | Budget refusal shape | not run: it needs a paid call or a priced mock, and no budget was approved. |
| G7 | Restore-key rotation | not run: it needs a full installation stack restored from a dump. It calls `/v2/key/info` and `/key/delete`, which G3 exercised. |

## Caddy 2.11.7 checks

Run with the engine's unchanged `services/box/ops/Caddyfile`, `LARES_DOMAIN=localhost` (Caddy's
internal certificate authority) and a mock upstream named `console` on port 3000.

| # | Check | Result |
| --- | --- | --- |
| C1 | `caddy validate` on the engine Caddyfile | **passed** ("Valid configuration"). |
| C2 | What the console receives | **partly passed.** Over HTTP/2, Host, `Origin`, `X-Forwarded-Proto: https` and `X-Forwarded-Host` reach the upstream exactly as with 2.11.4. A header named with a dot is dropped by 2.11.7 and kept by 2.11.4. A real console sign-in and its origin check were **not** run. |
| C3 | Long quiet stream | **passed.** A chunked NDJSON stream with two 130-second gaps arrived complete over both HTTP/2 and HTTP/1.1 (260 s, status 200). |
| C4 | Door webhook headers | not run: no door was configured. |
| — | Header size | A 16.5 KB header gets 431 over HTTP/2 under 2.11.7 (200 under 2.11.4). A 30 KB header gets 431 over HTTP/1.1 or a dropped HTTP/2 connection. A 12 KB cookie passes. Real console cookie sizes were not measured. |
